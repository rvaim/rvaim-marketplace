# HarmonyOS 官方设计指南

把本技能作为华为官方“通用设计基础”的本地规则库。先确定设备、主题和信息层级，再选择语义 Token；不要仅凭视觉印象拼凑“鸿蒙风格”。

## 执行流程

1. 明确目标设备：手机、折叠屏、平板、电脑、智慧屏、智能穿戴或智能座舱。
2. 明确浅色或深色模式、组件状态、信息层级、字体缩放和无障碍要求。信息不足时说明假设，不要把单设备数值冒充通用值。
3. 按任务读取对应参考资料：
   - 需要总体方向或多设备取舍时，读取 `references/foundations.md`。
   - 需要主题、文本、图标、容器、交互色时，读取 `references/color-system.md`，再从 `references/design-tokens.json` 取精确值。
   - 需要字号、字重、字体特性或排版审查时，读取 `references/typography.md`。
   - 需要应用启动图标时，读取 `references/app-icons.md`。
   - 需要系统功能图标或 Symbol 组件时，读取 `references/symbols.md`。
   - 需要透明材质与空间层级时，读取 `references/immersive-light.md`。
   - 需要圆角、间距或设备边距时，读取 `references/radius-spacing.md`，再从 `references/design-tokens.json` 取完整 Token。
   - 需要更新资料或给出出处时，读取 `references/sources.md`。
4. 优先输出语义 Token 名，再附当前设备和主题下的值。存在官方 Token 时不要只交付裸色值或随意尺寸。
5. 对设计或代码进行复核：检查深浅色成对映射、对比层级、状态覆盖、多设备差异、大字体、圆角层级、间距节奏、图标类型和沉浸光感可读性。

## 强制规则

- 把 `references/design-tokens.json` 中的颜色理解为 `#AARRGGBB`。前两位是透明度，不是 CSS 的 `#RRGGBBAA`。
- 为 Web 或其他只接受 RGB/RGBA 的目标生成代码时，显式转换 ARGB；不得直接调换或丢弃透明度。
- 同一语义 Token 在浅色和深色模式可对应不同值。不得通过简单反相推导另一主题。
- `font_on_*` 与 `icon_on_*` 用于品牌色、强调色或图片之上的反色内容，不要直接放在常规一级背景上。
- 界面背景色使用实色层级，不要擅自改成透明色。
- 自定义品牌色后，重新检查所有引用链、组件状态和对比关系，不要只替换一个十六进制值。
- 只使用官方全量表中实际存在的 Token；缺失的 level 不得按规律自行补齐。
- 沉浸光感只定义一次材质档位，由系统映射用户的强、均衡、弱三档偏好；不要为三档分别硬编码视觉实现。
- 同类、同层组件保持一致圆角和间距；视觉或功能层级越高，通常使用更大的圆角和更宽松的间距。
- 区分应用图标与 HarmonyOS Symbol：前者是 1024×1024px 的双层 PNG 资源，后者是具备字体属性的系统功能图标。
- 默认采用 HarmonyOS Sans。只有品牌或沉浸式场景确有必要时才建议自定义字体，并继续保证跨视距可读性和系统大字体适配。
- 官方页面的叙述与全量表偶有不一致；精确交付时保留已发布值并标出冲突，不能默默“纠正”。
- 本地资料核对日期为 2026-07-22。用户要求“最新”或目标 SDK 版本较新时，先按 `references/sources.md` 回查官方页面。

## 交付格式

设计方案至少说明设备、主题、层级和关键 Token。适合使用表格时按“对象、语义目的、Token、浅色值、深色值、设备差异、理由”组织。

审查结果先列会影响可读性、主题适配或多设备一致性的高优先级问题，再列视觉一致性问题。每条问题给出替代 Token 或参数，不要只说“不像鸿蒙”。

生成代码时沿用项目现有资源命名和主题机制；若项目没有设计 Token 层，先建立语义映射，再让组件引用语义名称。
