# 色彩系统

## 目标与基调

HarmonyOS 以宇宙蓝作为系统高亮基调，以带淡蓝色相的雪域灰承载基础背景。应用可以定义自己的品牌色，但品牌表达必须继续维持明确的层级、状态和可读性。

## 三层 Token

1. 基础 Token：`primary`、`on_primary`、`brand`、`container`、`background` 等基础角色，可直接使用或被语义层引用。
2. 语义 Token：固定表达文本、图标、组件或交互事件的用途，不要随意改变语义。
3. 控件 Token：只描述某个控件内部的唯一元素，不应跨控件复用。

## 核心角色

- `Primary`：最上层文本与图标；通过透明度或映射形成次级层次。
- `onPrimary`：强调色或图片之上的反色文本与图标；不要用于普通界面背景。
- `Brand`：主题与高亮色；变更后会影响所有引用品牌色的系统和自定义组件。
- `Container`：按钮、搜索框等组件的背景填充。

## 使用规则

- 同一个 Token 名在浅色和深色模式下保持语义一致，但数值可以变化。
- 基础色可通过透明度映射形成多个层级。自定义基础色时，同时复核语义层与控件层的引用链。
- 文本和图标采用一级、二级、三级、四级与高亮层级；依据内容优先级选用，不能只凭颜色深浅猜测。
- `comp_*` 用于组件容器，`interactive_*` 用于悬停、按压、获焦、激活、选择和点击等状态。
- 窗口背景通过不透明灰阶区分层级，避免多窗口或悬浮场景中背景融合。
- 官方说明称系统默认组合至少保障 3:1 对比度。具体产品如有更高无障碍标准，仍需按目标标准单独验证。
- 精确数值读取 `design-tokens.json`。其中 `systemColors` 为系统基础与语义表，`wearableColors` 为智能穿戴表。

## 已知官方资料差异

- 页面叙述提到 `comp_background_list_card` 和 `interactive_disable`，但同页“系统基础与语义 Token 全量表”没有给出它们的数值。不要自行推导。
- 页面背景说明与全量表中的部分深色值存在表述差异。精确规格以本地保存的全量表值为准，同时在落地目标 SDK 前回查系统资源。
- 智能穿戴表把 `icon_sub_emphasize` 的浅色值发布为 `#660a597f`。该值已原样保存，不要擅自改成看似更规律的值。

## 实现建议

1. 在资源层定义语义名称，组件只引用语义 Token。
2. 分别维护浅色和深色映射，不做运行时简单反相。
3. 将品牌色替换作为主题输入，自动覆盖所有相关文本、图标、容器和状态。
4. 对图片背景与强调容器单独检查 `on_*` 内容的对比度。
5. 将 ARGB 转成目标平台格式时保留 alpha，并在代码审查中检查字节顺序。
